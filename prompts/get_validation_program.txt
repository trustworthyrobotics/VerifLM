You are defining a semantic validation program for a MuJoCo robotic manipulation goal pose.

## Task

Instruction: {instruction}

Active object:

* Name: {active_object}
* Dimensions [x, y, z] (m): {active_dimensions}

Passive object:

* Name: {passive_object}
* Dimensions [x, y, z] (m): {passive_dimensions}

## Validation mode

Choose exactly one:

* `settling`: simulate the active object under gravity and validate its final settled state. Use when the task requires a stable, supported final placement.
* `geometric_only`: validate the proposed pose directly without simulation. Use when the intended goal is intentionally unsupported, such as a held pouring pose.

## Output

Return JSON only:

```json

  "required_contacts": [],
  "forbidden_contacts": [],
  "xyz_relations": [
    {
      "axis": "x | y | z",

    }
  ],
  "position_drift_tolerance": {

    "y": "strict | moderate | permissive",
    "z": "strict | moderate | permissive"

  "orientation_drift_tolerance": {
    "roll": "strict | moderate | permissive",
    "pitch": "strict | moderate | permissive",
    "yaw": "strict | moderate | permissive"
  },
  "reasoning": "brief explanation"
}
```

`required_contacts` and `forbidden_contacts` may contain only:

* `"active_passive"`
* `"active_table"`

## Rules

1. Use the **minimum set of constraints clearly required by the task**. Do not add uncertain or merely plausible constraints.

2. Use only whole-object relationships. Do not refer to semantic parts such as handles, rims, slots, pegs, branches, or spouts.

3. A required contact must exist in the validated state. A forbidden contact must not exist. Use an empty list when no contact is clearly required or forbidden.

4. XYZ relations compare the active object's center against the passive object's center. Add a relation only when the task clearly implies it. For example when placing a mug on a dish, the mug's center clearly should have a higher z. But when hangling a mug on a rack, the mug's center might not be clearly higher than the rack's center.

5. For `settling`, select drift tolerance independently for each axis:

   * `strict`: only small motion is acceptable.
   * `moderate`: some settling or reorientation is acceptable.
   * `permissive`: substantial motion is acceptable while still preserving task success.

6. For `geometric_only`, set both `position_drift_tolerance` and `orientation_drift_tolerance` to `null`.

7. Do not specify penetration thresholds, simulation duration, perturbations, or numeric tolerances. These are system-controlled.

Hints: 
- Think about whether the object needs to wobble around while settling (like hangling a mug on a branch), and if so allow a higher drift tolerance.
